### 1.5 踩到的数据层坑（26.3 schema，实测）

1. **`minecraft:air` 出现在战利品表 = 硬失败**：`IllegalStateException: Item must not be minecraft:air`，
   整个 `loot_table` 注册表失败 ⇒ 进不了世界。1.20.1 容忍。
2. **advancement 引用了不存在的 `trigger_type` = 硬失败**：`Unknown registry key in ResourceKey[trigger_type]`
   ⇒ 整个 `advancement` 注册表失败。删掉触发器类就必须同时删 advancement json。
3. **配方里引用不存在的 item/tag = 硬失败**：`Map entry 'P': … Missing tag: 'c:iron_plates'`。
   连 `minecraft:chain` 这种「原版改名」也会以「Not a tag id」的面目出现（`chain → iron_chain`）。
4. **`assets/<ns>/items/<id>.json` 必须生成**（从旧 `models/item/*.json` 批量生成），否则物品不可见。

### 2.3 判定：**不是一轮能完的**

三类硬伤叠加，与 `design-n-decor` 同型：

1. **registrate 垫片的泛型与上游不一致**（66 + 43 条）：上游 `BlockBuilder<T,P>` 的
   `transform/simpleItem/item(...)` 返回类型在垫片里都变了（垫片 `simpleItem()` 返回
   `BlockBuilder` 而上游返回 `ItemBuilder`），`customItemModel(...)` 这类 datagen 方法整个不存在。
   参考 `docs/fix-aero-registrate.md` §3.1 的做法（22 处同类已解），但 copycats 的量是这个的 4 倍。
2. **客户端模型系统是 mod 的**核心**：`CopycatModelFabric` / `UniversalMeshEmitter` /
   `CopycatRenderContextFabric` 直接在 `BakedModel` 层拼 quad（还带 Sodium/Indium/Athena 兼容）。
   26.3 的 renderpearl 把 `BakedModel`/`MultiBufferSource`/`VertexConsumer` 全换了，
   `docs/fix-aero-render.md` 的结论是这类**只能逐点降级**。降级掉模型 = 这个 mod 就没有意义了。
3. **配置 + mixin + JEI/EMI 集成**：config 12 文件（`FeatureToggle` 被 content 广泛引用）、
   2 个 mixin、2 个 recipe viewer。mixin 的 refmap 是 1.20.1 的，必须整块删。

**建议下一轮顺序**：① 先机械修 `ApiStatus`/JetBrains、`Identifier` 构造器、`useItemOn` 7 参、
`updateShape`、`ValueInput/Output`、`placeItemBackInInventory`（约 70 条，全是本文件 §1.3 表里
已经写好的通用改法）→ ② 删 config（`FeatureToggle` 一律 `true`）+ mixin + JEI/EMI +
datagen → ③ 最后只剩模型系统（估 300–500 条），单独一轮做。

**可复用资产**：`g8/_ep_bridge.py`（通用）、`g8/_crate_pkg.py`（通用）、`g8/_fix_esc_sem.py`
里的 26.3 改法表、`g8/_testworld.py`（进世界验收，自动重拷存档）。

## 3. 流水线本身的两条修正（本轮新增，建议并入 g8 正式流程）

1. **`_rewrite26.py` 没有 Create 包名迁移**：它只做 `net.minecraft` 的改名。
   1.20.1/1.21.1 的 Create 附属必须再跑一遍 **`_crate_pkg.py`**，否则 `com.simibubi.create`
   原样留着（这是 g7「542 错」的最大单一来源）。**注意 `net.createmod.catnip` 的 common/client
   划分不能按名字推**（`math.VecHelper` 在 common，`math.VecHelper` 的 client 侧也有一份；
   `lang.Lang`/`render.SpriteShiftEntry` 在 client）⇒ 必须按 create jar 的**类索引** resolve。
2. **`@ExpectPlatform` 桥接要单独一个 pass**：CFR 会把参数名丢成 `void varK_N;`，
   而且**每个 mod 都有**。`g8/_ep_bridge.py` 用「K = 参数下标」还原，13 个桥接一次过。
